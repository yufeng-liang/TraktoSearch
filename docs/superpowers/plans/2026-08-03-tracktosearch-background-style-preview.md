# TrackToSearch 页面背景风格预览 实现计划

> **面向 AI 代理的执行计划：** 在当前工作区内直接执行本计划，保持现有未提交 Android 改动不变。

**目标：** 创建一个独立的浏览器预览，用真实 App 页面骨架比较当前彩色弥散背景、单块 Soft Glow、Mesh Gradient 和 Aurora 四种背景风格，并观察它们与拟态玻璃卡片在浅色/深色模式下的搭配。

**方案：** 使用单文件静态 HTML/CSS/JavaScript。页面提供背景风格、App 页面和明暗模式三个控制维度；手机画布内只模拟搜索、发现、我的、设置的代表性内容，不接入 Android 业务数据。背景通过 CSS 多层 radial/conic gradient 实现，玻璃卡片通过半透明底色、backdrop-filter、边框、内外阴影和顶部高光复刻现有 Compose 组件的视觉特征。

**验证：** 启动可视化伴侣本地服务器，在浏览器中检查控件切换、四页内容渲染、浅深色切换、手机画布响应式尺寸和 `prefers-reduced-motion` 行为；同时运行静态 HTML 结构检查与 `git diff --check`。

### 任务 1：建立独立预览页面

**文件：**
- 创建：`docs/previews/tracktosearch-background-styles.html`

- [ ] 使用语义化 HTML 搭建预览控制栏、手机画布和底部导航。
- [ ] 为四种背景提供明确的 CSS 状态类，并为四个 App 页面提供可切换的代表性内容。
- [ ] 复刻现有拟态玻璃卡片的浅色/深色材质，同时保证移动端不产生页面级横向溢出。
- [ ] 加入键盘焦点、减少动态效果和不依赖外部资源的视觉资产。

### 任务 2：启动并验证浏览器预览

**文件：**
- 读取/展示：`docs/previews/tracktosearch-background-styles.html`
- 可视化伴侣临时屏幕：由本地预览服务器的 `screen_dir` 管理

- [ ] 启动本地预览服务并确认 `server-info` 存在且服务未停止。
- [ ] 将最新预览推送到服务目录，确认风格、页面、主题切换均可操作。
- [ ] 检查宽屏和窄屏布局、文字边界、卡片层级与控制项可见性。
- [ ] 运行 `git diff --check` 与 HTML 关键结构搜索，记录验证结果。

### 任务 3：交付预览

- [ ] 保留已有 Android 未提交改动，不修改或清理无关文件。
- [ ] 向用户提供带会话 key 的本地预览地址，并说明当前默认展示内容。
