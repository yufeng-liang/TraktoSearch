# 公开邀请码直接发送与重发设计

## 目标

用户在官网提交用户名和邮箱后，系统直接创建朋友记录和一次性邀请码，并把邀请码发送到该邮箱。不再要求用户先点击邮箱验证链接。

用户在首次邮件未收到时，可在 60 秒冷却结束后点击重发。重发会立即撤销之前的邀请码，生成一个新的邀请码并发送；新邀请码继续有效 72 小时。

## 方案

### 申请流程

1. 官网提交用户名和邮箱。
2. Gateway 转发到 Worker 的公开申请接口。
3. Worker 保留现有限流、邮箱规范化和过期名额释放逻辑。
4. Worker 原子创建 `friends`、`invites` 和 `invite_requests` 记录，立即占用一个正式名额。
5. Worker 发送包含邀请码的 Brevo 事务邮件，接口只返回 `INVITE_SENT`，不在 HTTP 响应中返回邀请码。
6. 同一邮箱重复提交时不创建第二个朋友，只返回通用成功结果，避免暴露邮箱是否存在。

邮箱不再作为所有权验证因素；安全边界由 200 个正式名额、每 IP 每小时 3 次限流、同一邮箱幂等和邀请码一次性使用共同承担。

### 重发流程

新增公开重发接口，官网只提交邮箱：

1. 查找该邮箱对应的公开申请朋友和当前未使用邀请码。
2. 检查上次邮件发送时间，未满 60 秒时返回 `RESEND_COOLDOWN` 和剩余秒数。
3. 生成新邀请码。
4. 通过 D1 batch 原子撤销旧邀请码、创建新邀请码、更新申请记录指向新邀请码并记录重发审计日志。
5. 发送新邮件，更新发送时间。
6. 发送失败时不恢复旧邀请码；新邀请码仍可在下一次 60 秒冷却后重发，避免旧码在用户不知情时重新有效。

并发重发通过旧邀请码的条件更新防止重复轮换；只有成功撤销当前旧码的请求可以建立新码。

### 邮件内容与布局

- 直接发送的邮件主题为“欢迎加入 TraktoSearch，你的邀请码已送达”。
- 使用响应式 table 布局，外层宽度为 `100%`，内容区 `max-width: 600px`，移动端左右内边距为 `16px`，避免 QQ 邮箱窄屏横向裁切。
- 同时提供 HTML 和纯文本正文。
- 邀请码区块下方显示官网静态资源：
  `https://tracktosearch.pages.dev/assets/chiikawa/ai-chiikawa-love.png`
- 图片使用响应式宽度，最大约 180px；邮件引用 HTTPS 资源，不把 321 KB 图片编码进邮件正文。

官网构建会把 `F:\website-trakt\assets\chiikawa\` 复制到生产 `dist/assets/chiikawa/`，部署后先验证图片 URL 返回 200，再部署 Worker。

### 官网交互

- 首次提交成功后显示“邀请码已发送，请检查收件箱”。
- 保留邮箱输入值，显示重发控件。
- 重发控件初始禁用，倒计时 60 秒；倒计时结束后启用。
- 重发成功后重新开始 60 秒倒计时，并显示“新的邀请码已发送，之前的邀请码已失效”。
- 申请失败、冷却中、名额已满等状态使用接口错误码映射为明确提示。

## 验证

- Worker 单测覆盖直接发码、Brevo 邮件 HTML、邀请码轮换、60 秒冷却、并发条件更新和发送失败状态。
- Worker 全量测试与 TypeScript 检查通过。
- 官网构建和静态资源检查通过。
- 部署后验证 Worker/Gateway `/health`、图片 URL、官网申请和重发接口。
- 真实邮箱验收至少确认首次邮件和重发邮件各一封，确认旧邀请码无法激活、新邀请码可以激活。
