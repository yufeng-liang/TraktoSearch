# 激活庆祝与反馈入口优化设计

## 状态

头脑风暴阶段已确认设计，待文档审阅后进入实现计划。

## 背景与目标

本次调整包含三个彼此独立但都属于 App 端体验优化的改动：

1. 用户首次成功激活后，在激活页左右两侧播放彩色礼花，明确表达庆祝。
2. 新反馈页移除联系方式输入栏，降低提交负担，同时保留服务端和历史数据兼容性。
3. 反馈列表页在现有写新反馈入口上方增加温暖、有趣的说明文案，鼓励用户提交建议。

## 已确认的设计决策

| 决策项 | 选择 |
|---|---|
| 礼花方向 | 彩色庆祝风格 |
| 礼花资源 | 复用现有 `easter_firework.json` Lottie 资源 |
| 礼花位置 | 激活卡片两侧，左侧向屏幕中央倾斜 `40°`，右侧向屏幕中央倾斜 `-40°` |
| 礼花触发 | 仅触发 `activated: false -> true` 的状态转变 |
| 已激活用户进入页面 | 不播放礼花 |
| 礼花持续时间 | 播放一次，约 2～3 秒后淡出 |
| 激活成功后的导航 | 保持当前页面，继续展示 Trakt 登录和游客入口 |
| 新反馈联系方式 | 移除页面输入和客户端提交参数 |
| 服务端联系方式字段 | 保留 `contact` DTO、数据库字段和历史详情展示 |
| 反馈引导入口 | 保留现有整行加号卡片，不改为悬浮按钮 |
| 引导文案位置 | 加号卡片正上方 |
| 引导文案 | `每一条反馈，我都会认真读到。这里也是你的功能许愿池，说不定哪天，你许下的愿望就上线啦～` |
| 本地化 | `values/`、`values-zh/`、`values-ja/`、`values-ko/` 同步 |

## 激活页设计

### 用户流程

1. 页面加载时记录当前 `authState.activated` 状态。
2. 只有当状态从 `false` 变为 `true` 时，显示庆祝层。
3. 左右两份礼花同时进入播放状态；右侧做水平镜像，并向屏幕中央倾斜。
4. 礼花播放结束或达到约 3 秒超时后淡出。
5. 页面继续停留在激活成功状态，Trakt 登录和游客入口保持可操作。

已经激活的用户重新进入页面时，初始状态直接视为已观察状态，不触发庆祝。礼花动画不参与导航，也不改变认证状态。

### 视觉与布局

- 使用现有暖色影院背景和激活卡片，不修改全局主题。
- 礼花位于主内容两侧、靠近激活卡片上方，避免覆盖标题、输入框、错误信息和按钮。
- 左侧礼花相对屏幕水平线向内倾斜 `40°`；右侧礼花向内倾斜 `-40°`。
- 礼花层不添加点击处理，不拦截输入框、Trakt 登录和游客入口的触摸事件。
- 礼花是纯装饰，内容描述为空，避免无障碍服务重复播报。
- 若 Lottie 组合加载失败，隐藏庆祝层，不影响激活成功状态和后续操作。

### 组件与状态边界

新增屏幕级 `ActivationCelebration` Compose 组件，负责：

- 加载 `R.raw.easter_firework`；
- 绘制左右两份 Lottie，并应用镜像和内倾角；
- 使用一次迭代播放和淡入/淡出；
- 在动画完成或超时后通知页面关闭庆祝层。

`ActivationLoginScreen` 负责监听 `AuthUiState.activated` 的状态转变。认证协议、邀请码校验、错误映射和导航回调均不修改。

## 反馈页设计

### 新反馈页

- 删除 `contact` 本地状态和联系方式 `OutlinedTextField`。
- `FeedbackViewModel.submit` 和 `FeedbackRepository.submit` 不再从 UI 接收联系方式。
- `SubmitFeedbackRequest.contact` 保留为可空兼容字段，提交时固定为 `null`。
- `feedback_contact`、`feedback_contact_placeholder` 仅用于输入栏，随输入栏从四套资源中移除。
- `feedback_contact_value` 继续保留，用于旧反馈详情展示历史联系方式。
- 类型选择、正文校验、截图上传、提交进度、错误恢复和成功返回行为保持不变。

### 反馈列表页

在现有“写新反馈”整行卡片之前增加一个辅助说明文本，使用 `bodySmall` 或同等紧凑文字样式、`onSurfaceVariant` 颜色，允许自然换行但不改变卡片结构。

中文文案：

> 每一条反馈，我都会认真读到。这里也是你的功能许愿池，说不定哪天，你许下的愿望就上线啦～

建议的其他语言文案：

- English: `I read every piece of feedback carefully. This is also your feature wish pool—maybe one day, your wish will make it into the app~`
- 日本語：`届いたフィードバックは、一つひとつ私が大切に読みます。ここは機能の願いごとボックスでもあります。いつか、あなたの願いが実現するかも〜`
- 한국어: `남겨 주신 피드백은 제가 하나하나 꼼꼼히 읽어요. 여기는 기능 소원함이기도 하니, 언젠가 당신의 바람이 이루어질지도 몰라요~`

反馈列表为空、有数据、加载失败或重试时，这段说明都保留在写新反馈入口上方，确保用户始终能看到提交入口的用途。

## 数据与兼容性

- 不修改 `feedback-worker` 路由、D1 schema 或后台页面。
- 不清理已有反馈记录中的联系方式。
- Android 新提交不再收集或发送用户联系方式。
- 其他反馈字段、截图上传顺序、缓存和详情展示逻辑保持不变。

## 验证方案

### 自动化验证

1. 增加或调整激活页行为测试，覆盖：初始已激活不播放、未激活到已激活播放一次。
2. 增加反馈提交契约测试，确认新提交的 `contact` 为 `null`，其余字段不变。
3. 保留反馈接口和历史详情的兼容性测试，确认旧详情仍可解析和展示联系方式。
4. 检查四套资源都包含新的引导文案，且输入专用联系方式资源无残余引用。

### 构建与运行验证

- 执行针对性 Android 单元测试。
- 执行 `:app:compileDebugKotlin` 和 debug 构建。
- 在模拟器上验证一次真实激活后的礼花位置、左右 `40°` 内倾、动画淡出和按钮可用性。
- 重新进入已激活页面，确认不会重复播放礼花。
- 打开反馈列表和新反馈页，确认文案位置、联系方式栏移除和正常提交。

## 非目标

- 不自动从激活页跳转到 Trakt 或主界面。
- 不新增礼花依赖或重新设计登录页背景。
- 不将反馈入口改造成悬浮按钮。
- 不删除后端联系方式字段或迁移历史数据。
- 不修改与本次体验无关的帮助页、反馈详情页和反馈后台。
