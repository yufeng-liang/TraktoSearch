# Watchlist 搜索入口与分类 Tab 设计

- 日期：2026-08-11
- 状态：已完成需求确认，待实现
- 范围：`WatchlistScreen` 顶部搜索交互与电影/电视剧/其他分类 Tab

## 1. 目标

将 Watchlist 页的搜索框收敛为标题栏右侧的搜索入口，减少顶部占用，同时保留现有搜索能力、筛选入口和想看/已看切换。分类 Tab 重新设计为独立的 Watchlist 组件，强化文字层级与数量信息，并提供稳定、无回弹的选中放大过渡。

## 2. 已确认决策

### 2.1 顶部操作顺序

标题栏右侧从左到右固定为：

`搜索` → `筛选` → `想看/已看`

三者作为右侧操作组对齐。搜索图标和筛选图标都使用现有拟态圆形图标按钮样式，已看/想看继续使用现有切换条。

### 2.2 搜索收起态

- 搜索框收起后只显示搜索图标。
- 搜索文字和过滤结果继续保留，不因收起而清空。
- 当搜索文字非空时，搜索图标使用主题色提示当前仍有搜索条件；为空时使用普通前景色。
- 筛选按钮移动到同一标题栏操作组，原搜索行不再保留空槽。
- 分类 Tab 直接上移到标题栏下方，不新增“分类”标题。

### 2.3 搜索展开态

- 点击搜索图标后，搜索框从图标位置向左展开。
- 搜索框右边缘固定在筛选按钮左侧，左侧动态占满安全边距内的可用空间，可覆盖标题“我的”，但不遮挡筛选按钮和想看/已看切换条。
- 展开时自动请求焦点并弹出系统键盘。
- 输入框内部沿用现有结构：左侧搜索图标、中间占位提示或输入内容、右侧有内容时显示清除按钮。
- 搜索过滤和无结果时的 Trakt 搜索行为保持现状，不新增网络逻辑。

### 2.4 搜索关闭与返回

- 点击搜索框外部区域自动收起搜索框。
- 点击筛选按钮或想看/已看切换条时，先收起搜索框，再继续执行本次点击对应的原有操作。
- 点击标题或列表区域时只收起搜索框，不改变其他状态。
- 展开且键盘显示时，第一次返回只关闭键盘并保持搜索框展开；键盘已关闭后再次返回才收起搜索框。
- 列表滚动不会自动收起搜索框。
- 收起和展开使用约 240ms 的平滑宽度过渡，不使用回弹或脉冲动画。

## 3. 分类 Tab 设计

### 3.1 组件边界

新增文件：`app/src/main/java/com/tracktosearch/ui/screen/watchlist/WatchlistCategoryTabs.kt`

新增 Watchlist 专用组件，不修改全局 `CapsuleTabSelector`，不影响发现页等其他页面。

建议组件接口：

```kotlin
internal data class WatchlistCategoryTab(
    val label: String,
    val count: Int
)

@Composable
internal fun WatchlistCategoryTabs(
    tabs: List<WatchlistCategoryTab>,
    selectedIndex: Int,
    onTabSelected: (Int) -> Unit,
    modifier: Modifier = Modifier
)
```

组件只负责布局、语义、视觉状态和动画。数量由 `WatchlistScreen` 根据现有过滤结果和加载状态计算后传入。

### 3.2 布局与文字

- Tab 直接位于标题栏下方，上方不显示“分类”文字。
- 三项使用稳定的等宽触控区，避免名称或数量变化导致相邻 Tab 跳动。
- 分类名称使用更大的字号，目标约为 16–17sp，并通过主题排版和字重适配不同语言。
- 数量从原来的 `电影(0)` 文本中拆出，显示为独立的柔和胶囊徽标；名称和数量仍属于同一个 Tab 语义单元。
- 数量徽标支持多位数，宽度可随内容增长，但 Tab 的整体触控区和布局测量保持稳定。
- 颜色使用当前主题的 `primary`、`onSurfaceVariant` 和表面色，不固定写死截图中的棕色。

### 3.3 选中态与动画

- 选中项使用轻玻璃表面、主题色文字和主题色数量徽标。
- 名称与数量徽标作为一个整体使用 `scale = 1.05f` 的绘制缩放。
- 选中项放大后保持放大状态；切换到其他项时，旧选中项平滑恢复 `scale = 1f`，新选中项平滑放大到 `1.05f`。
- 过渡时长约 240ms，不使用过冲、回弹或点击后自动恢复。
- 缩放只影响绘制，不改变布局测量和触控区域，避免相邻项移动。
- 深色模式使用同一状态模型，但通过主题表面和前景色保证对比度。

## 4. 状态与交互模型

| 状态 | 视觉 | 操作结果 |
|---|---|---|
| 搜索收起、无查询 | 普通搜索图标 | 点击后展开、聚焦并弹出键盘 |
| 搜索收起、有查询 | 主题色搜索图标 | 点击后恢复原查询并聚焦 |
| 搜索展开、键盘显示 | 动态宽搜索框 | 输入实时过滤；第一次返回隐藏键盘 |
| 搜索展开、键盘隐藏 | 动态宽搜索框 | 第二次返回或点击外部区域收起 |
| 分类 Tab 未选中 | 普通文字与弱化数量徽标 | 点击后成为选中项 |
| 分类 Tab 选中 | 轻玻璃底、放大 5%、主题色徽标 | 保持放大直到选择其他 Tab |
| 切换分类 | 新旧 Tab 同时过渡 | 旧项缩回，新项放大，内容按现有过滤逻辑更新 |

## 5. 实现约束

- `searchQuery`、筛选状态、`selectedMode`、`selectedTab` 和现有过滤函数继续作为数据源，不复制过滤逻辑。
- 搜索展开状态使用 `rememberSaveable`，避免旋转或进程恢复时丢失已确认的交互状态。
- 使用 `FocusRequester` 和键盘控制器处理展开聚焦；返回处理依据 IME 可见状态区分隐藏键盘与收起搜索框。
- 搜索框使用稳定的容器尺寸和 `zIndex`，动态宽度动画不得改变筛选按钮和切换条的测量位置。
- 外部点击检测不得吞掉筛选按钮、切换条和列表自身的点击事件；目标操作应继续收到原有回调。
- Tab 使用可选中语义和至少 48dp 的触控尺寸；选中状态应暴露给无障碍树。
- 所有用户可见文案继续使用 `stringResource`；数量不新增硬编码文案。
- 不修改数据层、网络层、全局 Tab 组件或其他页面。

## 6. 测试与验收

### 6.1 Compose/UI 测试

新增或扩展 Watchlist UI 测试，覆盖：

1. 收起态显示搜索图标，展开后显示输入框并请求焦点。
2. 展开态输入仍更新现有搜索过滤结果。
3. 有查询时点击外部区域只收起，不清空查询。

5. 键盘显示时第一次返回只隐藏键盘；键盘隐藏后再次返回才收起搜索。
6. 搜索框展开宽度受筛选按钮约束，不遮挡右侧操作按钮。
7. 分类 Tab 显示独立数量徽标，切换后旧项恢复原大小、新项保持放大。
8. 分类 Tab 触控区域稳定，数量变化不会导致相邻项重排。

## 7. 风险与回退

- Android 输入法可能优先消费返回事件；实现需同时依据 IME 可见状态和搜索展开状态处理，确保最终符合两次返回约定。
- 过大的缩放可能与相邻 Tab 重叠；固定 `1.05f` 上限并保持触控区等宽，必要时只调整绘制层间距，不改变语义布局。
- 动态宽度和标题遮挡可能在窄屏设备上压缩输入区域；保留最小输入宽度，无法满足时优先保证筛选和切换按钮可用。
- 若设备或编译环境不具备插桩条件，必须分开报告源码、构建和设备验证证据，不以编译成功替代运行验收。

## 8. 非目标

- 不修改发现页的 `CapsuleTabSelector`。

- 不增加新的用户帮助页面内容；本次没有新增独立业务功能，仅调整既有入口和视觉交互。
