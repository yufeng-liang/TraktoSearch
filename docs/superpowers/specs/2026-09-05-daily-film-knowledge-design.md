# 今日影视知识与跨学科答题设计

日期：2026-09-05

状态：待用户审阅

## 1. 背景与目标

AI 精灵中心已经具备每日影视内容和影视知识答题能力，但“每日影视冷知识”容易把产品目标带向追求冷门事实，且 AI 生成内容可能出现关联泛化、证据不足、学科硬套、来源可达但不支持结论等问题。

本设计将功能统一为“今日影视知识”，目标是让用户每天从看过的影视中理解一个具体概念，并能通过一道即时小题完成一次轻量回忆和迁移。内容可以来自影视情节、影视创作、历史背景、科学现象或观影主题延伸，但必须区分事实、观影解读和通用科普。

本设计同时覆盖：

1. 共享学习单元：每日知识和影视知识答题使用同一份影视证据、概念和边界。
2. 内容质量：候选生成、二次 AI 审校、本地硬门槛、失败降级和人工审核种子知识。
3. 学科扩展：内部支持丰富学科，UI 使用八个大类，按证据等级控制生成范围。
4. 每日体验：每天一条主内容，最多两次主动换题，当天内容稳定可回看。
5. 图文表达：复用 TMDB / 豆瓣真实剧照，并由 Worker 后台生成 AI 概念插图。
6. UI/UX：主知识卡、影视依据、概念解释、即时小题、来源边界和反馈形成渐进式阅读流程。
7. 国际化、无障碍、离线历史、图片缓存和服务端安全。

## 2. 范围与非目标

### 2.1 本次范围

- 将产品文案和功能定位从“每日影视冷知识”调整为“今日影视知识”。
- 建立共享学习单元数据结构，作为每日知识和答题的共同内容源。
- 扩展学科目录和证据等级，支持自然引入心理学、社会学、历史、马克思主义哲学、物理、化学及其他影视相关领域。
- 保留现有 13 题答题协议：10 道单选、2 道多选、1 道简答。
- 每日知识增加 1 道不计入正式成绩的即时小题。
- 每日知识支持最多两次主动换题，并记录当天已展示的内容，避免重复。
- 复用现有 TMDB backdrop、豆瓣剧照和海报资源。
- Worker 服务端接入 Agnes 概念插图生成，后台预生成并写入 R2 或等价持久化资源。
- AI 生成内容按 `locale` 返回，缓存按语言隔离。
- 本地保留最近 30 天或 50 条知识，支持离线回看。
- 增加正文渐进展开、剧透提示、来源与边界、反馈和无障碍行为。
- 保留旧客户端、旧缓存和旧字段的读取兼容。

### 2.2 非目标

- 不把功能做成无限刷新的短视频信息流。
- 不要求每天覆盖固定学科，不为完成学科配额硬套物理、化学或医学。
- 不建设完整百科、知识图谱、社交学习、排行榜、积分、连续打卡或复杂勋章系统。
- 不新增每日专用的高频搜图或爬图链路。
- 不使用 AI 插图冒充真实剧照、历史现场或影片截图。
- 不让 AI 根据片名、颜色或单个画面猜测具体化学物质、诊断结果或危险操作。
- 不把角色分析写成临床诊断，不提供现实医疗、法律、投资、武器或入侵操作建议。
- 不要求每张 AI 插图都经过另一个视觉模型审核；第一期采用技术校验、提示词约束和版本抽样验收。
- 不因图片生成失败阻断文字知识、即时小题、正式答题或反馈。

## 3. 产品定位与内容类型

### 3.1 产品定位

产品文案统一使用“今日影视知识”作为功能名称。内容目标为：

> 有影视关联、有具体证据、能在 1～2 分钟内学会一个可复述的概念。

“冷”不是质量指标。冷门内容只有在确实有影视关联、可核验且有学习价值时才保留。

### 3.2 三种关联等级

每条内容必须明确关联等级：

| 关联等级 | 条件 | 用户可见标签 |
| --- | --- | --- |
| 直接关联 | 有具体剧情、角色行为、制作资料、历史材料或可靠外部证据 | 看过的影视 |
| 主题延伸 | 从用户片单的主题、类型或观看结构延伸，但不是某部影片直接表达 | 观影延伸 |
| 通用科普 | 没有可靠的个性化关联，使用审核过的影视知识单元 | 影视科普 |

关联等级不是个性化分数，不向用户展示“关联度 87%”等伪精确数字。

### 3.3 内容证据模式

内容还必须区分：

- `film_fact`：影片或媒体资料中可直接确认的事实。
- `viewing_interpretation`：基于影片内容的合理观影解读，不是影片直接引用的理论。
- `external_fact`：需要可靠外部来源支持的历史、科学、幕后或制度事实。
- `theme_extension`：由用户片单主题延伸出的知识，不宣称来自某部影片。

事实、解读和延伸必须在数据层分开，在 UI 中用内容边界说明辅助用户理解。

## 4. 共享学习单元

### 4.1 设计原则

每日知识和答题不再各自自由生成。先生成并审校学习单元，再由不同功能把同一单元转换成阅读内容或题目。

```text
影视资料
  ↓
证据整理
  ↓
学习单元候选
  ↓
二次 AI 审校与重写
  ↓
本地质量门槛
  ↓
每日知识 / 即时小题 / 13 题闯关
```

### 4.2 学习单元字段

逻辑结构如下，具体序列化字段可以在实施阶段按现有 DTO 约定命名：

```json
{
  "id": "knowledge-unit-id",
  "version": 1,
  "locale": "zh-CN",
  "relationType": "direct_watch",
  "evidenceMode": "viewing_interpretation",
  "subjectGroup": "people_and_mind",
  "subject": "社会心理学",
  "concept": "从众压力",
  "title": "为什么第一个提出异议的人很重要？",
  "takeaway": "人在群体已经形成共识时，第一个表达异议的人往往先降低其他人表达不同意见的心理成本。",
  "relatedMedia": {
    "title": "十二怒汉",
    "mediaType": "movie",
    "traktId": 123,
    "tmdbId": 550,
    "doubanId": null
  },
  "filmEvidence": "陪审团第一次投票后，少数意见逐渐获得公开讨论的空间。",
  "explanation": "……",
  "realWorldExample": "……",
  "boundary": "这是基于影片场景的入门解读，不是对角色的临床诊断。",
  "difficulty": "easy",
  "spoilerLevel": "light",
  "source": {
    "name": "来源名称",
    "url": "https://example.com",

  },

    "prompt": "……",

  }

```

### 4.3 兼容字段

当前已有的 `title`、`fact`、`explanation`、`sourceName`、`sourceUrl`、`publishedAt`、`characterLine`、`relatedMediaTitle`、`containsSpoiler` 等字段继续保留读取能力。

新字段以可选字段或版本化响应形式增加。旧客户端不识别新字段时，仍可展示旧的正文和来源；新客户端优先使用结构化字段。

旧缓存必须继续可读。学习单元版本变化时使用新的缓存键或版本字段，不原地破坏历史记录。

## 5. 学科目录和生成门槛

### 5.1 UI 八个大类

用户界面只展示以下八个大类：

```text
影视表达
人与心理
社会与制度
历史与文化
哲学与伦理
科学与自然
技术与未来
生活与职业
```

### 5.2 内部具体学科

内部目录支持：

```text
电影学、叙事学、摄影与视觉设计、剪辑与声音、表演与戏剧
心理学、认知科学、发展心理学、教育学
社会学、人类学、传播学、政治学、经济学、法学、犯罪学
历史、文化研究、语言学与符号学、宗教神话与民俗、音乐与艺术史
哲学与伦理学、马克思主义哲学
物理、化学、生物与生态、医学与公共卫生、天文学、地理与气候
计算机与人工智能、数学与统计、工程与材料、建筑与城市规划
体育科学、军事学与战略、食品科学、职业与组织知识
```

UI 不展示全部具体学科列表，题卡只突出一个主学科和一个具体概念。

### 5.3 学科等级

#### 常规开放

有剧情简介或基本影视证据即可使用：

```text
电影学、叙事学、摄影、剪辑、声音、表演
心理学、认知科学、社会学、人类学、传播学
经济学、历史、哲学、伦理学、马克思主义哲学
语言学与符号学、文化研究
```

#### 证据增强开放

需要明确影片现象、可靠媒体资料或外部来源：

```text
物理、化学、生物、天文学、地理
计算机与人工智能、数学、工程、建筑
医学、法学、军事学、体育科学、食品科学
```

#### 高风险隔离

不自动生成可执行建议：

```text
现实个体医疗诊断和治疗方案
药物剂量
现实案件法律结论
危险化学品制备
武器制造或攻击步骤
网络入侵和绕过安全措施
当前政治事件的立场操纵
高风险金融操作建议
```

高风险领域可以保留历史、制度、伦理和基础背景科普，但必须避免现实行动指导。

### 5.4 学科使用规则

- 每日内容只有一个主学科，最多一个辅助视角。
- 13 题闯关自然覆盖 3～5 个学科，不固定覆盖所有学科。
- 物理和化学只有输入资料确实支持时才使用。
- 心理学不得对角色作临床诊断。
- 历史必须区分历史事实、影片改编和 AI 解读。
- 马克思主义哲学必须绑定具体冲突、条件变化或实践经验，禁止只输出口号。
- 科学内容必须说明适用条件，并区分影视夸张与现实原理。

## 6. AI 内容质量链路

### 6.1 两阶段文本生成

第一阶段生成候选内容，第二阶段作为审校员重写或拒绝。

第二阶段只能使用：

```text
候选学习单元
客户端提供的影视资料
外部来源摘要或来源证据
系统规定的学科边界
```

审校员不得补写输入中不存在的：

```text
剧情、台词、镜头、演员、历史因果、实验数据、幕后事实
```

### 6.2 必须满足

每条每日知识必须有：

- 一个核心概念。
- 一部主关联影视或明确的主题延伸说明。
- 一个具体影视依据。
- 一句用户可以复述的学习结论。
- 明确关联等级和证据模式。
- 明确片透等级。
- 外部事实对应来源和来源依据。
- 与内容类型匹配的边界说明。
- 一道来自同一学习单元的即时小题。

### 6.3 必须拒绝

以下内容不允许靠润色返回：

```text
这部电影展现了人性的复杂性。
这部作品告诉我们要勇敢面对困难。
影片体现了社会对个体的影响。
这部电影非常具有教育意义。
```

拦截条件包括：

- 删除片名后仍然是完全通用的套话。
- 只引用片名、年份或类型，没有具体依据。
- 依据和结论之间没有明确连接。
- 把分析写成确定事实。
- 来源 URL 可达，但来源不支持当前结论。
- 物理、化学或医学概念缺少适用条件。
- 生成了输入没有提供的剧情、台词、场景或人物动机。
- 片透等级低于实际内容。
- 关联影视不在用户已看列表中。

### 6.4 长度建议

默认浅阅读内容：

```text
标题：12～28 个中文字符
学习结论：35～70 个中文字符
影视依据：40～100 个中文字符
概念解释：80～160 个中文字符
现实延伸：40～100 个中文字符
默认阅读量：180～320 个中文字符
展开后上限：450～600 个中文字符
```

不同语言按信息密度和自然表达调整，不进行机械字符数翻译。

### 6.5 本地硬门槛

Worker 本地检查：

- JSON 结构完整。
- 字段类型正确。
- 关联媒体 ID 或标题合法。
- 证据文本来自输入资料或来源摘要。
- 关联等级与输入资料匹配。
- 学科在受控目录内。
- 学科与概念非空且具体。
- 学习结论不是泛化套话。
- 题目、选项和解析逻辑一致。
- 即时小题只有一个明确最佳答案。
- 选项文本和 ID 唯一。
- 片透等级和内容一致。
- 来源 URL 为合法 HTTP(S)，来源证据非空。
- 外部事实必须同时存在来源名称、URL 和来源依据。

二审失败、结构异常或本地门槛失败时，绝不返回第一阶段候选。

## 7. 内容选择、刷新和重复控制

### 7.1 每日内容数量

- 每天一条主内容。
- 用户最多主动换两条。
- 当天第一次成功内容稳定保留。
- 片单后台同步不自动替换当天主内容。
- 只有用户主动换题或明确重新生成才生成新内容。

### 7.2 候选选择顺序

```text
有证据的用户已看影视
  ↓
排除近期重复的影视、概念和学科
  ↓
选择最容易讲清一个概念的候选
  ↓
没有合适候选时使用主题延伸
  ↓
仍没有合适候选时使用审核种子知识
```

重复控制建议：

- 同一影视 7 天内尽量不重复。
- 同一概念 14 天内不重复。
- 同一主学科不连续重复超过两天。
- 同一内容类型不连续重复超过两天。
- 用户片单过少时允许放宽影视限制，但必须换概念或证据角度。

### 7.3 审核种子知识库

首期维护约 24～36 条人工审核的通用影视知识单元，每个 UI 大类 3～5 条。每条包含可靠来源、概念、学习结论、边界和即时小题。

AI 可以调整标题、语气和难度，但不能改变种子知识的核心事实和适用条件。

## 8. 每日知识 UI/UX

### 8.1 页面结构

```text
标题栏：今日影视知识 + 日期 + 最近学过
↓
主知识卡：标题 + 今天学到
↓
影视依据区：剧照 + 片名 + 具体依据
↓
概念解释区：短解释 + 展开深入
↓
即时小题：一题回忆与迁移
↓
精灵台词：轻量陪伴
↓
反馈、内容边界、来源与依据
```

### 8.2 主知识卡

最突出信息为：

```text
今天学到
```

主知识卡只展示一个结论，避免把来源、发布时间、多个彩色标签和长解释挤进首屏。

### 8.3 影视依据区

展示：

```text
关联等级
影视标题
真实剧照或影视关联图
剧照说明
具体影视依据
```

关联等级使用自然文案：

```text
看过的影视
观影延伸
影视科普
```

不展示算法评分。

### 8.4 概念解释区

默认显示简短解释，点击后展开：

- 现实生活例子。
- 事实与解读边界。
- 影片表现与现实原理的差异。
- 适用条件和反例。

正文立即完整显示，不使用逐字打字机动画。解释区可以使用 100～180ms 轻微淡入。打开缓存或历史内容时不重复播放动画。

### 8.5 即时小题

- 由同一学习单元生成。
- 只展示 1 道题。
- 2～4 个选项。
- 不计入正式 13 题成绩。
- 不额外触发 AI 请求。
- 答题后立即显示正确答案和解析。
- 解析回到“影视证据 → 学科概念 → 学习结论”。
- 难度反馈为“太简单 / 刚刚好 / 有点难”。

### 8.6 底部操作

默认：

```text
来一道题    换一条
```

答题后：

```text
查看解析    进入知识闯关
```

内容反馈：

```text
有帮助
太泛
关系弱
太难
片透多
```

“换一条”不能成为视觉上最强的主操作。

## 9. 真实剧照与 AI 概念插图

### 9.1 图片角色

图片必须区分：

```text
media_still：真实剧照，可作为场景证据
media_reference：影片画面，但不证明当前知识
media_poster：影视关联图，只确认作品身份
concept_illustration：AI 生成概念插图，只辅助理解
```

### 9.2 真实图片来源优先级

```text
已有 TMDB backdrop 缓存
  ↓
已有豆瓣剧照缓存
  ↓
现有媒体资源管线可获取的剧照
  ↓
海报
  ↓
AI 概念插图
  ↓
纯文字
```

每日知识不新增独立搜图或爬图链路。图片加载失败不影响正文。

真实剧照由媒体数据层基于媒体 ID 选择，AI 不返回或猜测真实剧照 URL。

### 9.3 AI 概念插图

统一使用低饱和 editorial illustration 风格：

- 不生成真实演员或可辨认的人物肖像。
- 不复刻具体电影镜头。
- 不生成伪纪录历史照片。
- 不加入文字、字幕、水印或复杂标签。
- 不展示危险化学、武器或入侵步骤。
- 不让图片承担事实证明责任。
- 学科名称和概念文字由 App 叠加，不交给模型生成。

### 9.4 后台预生成

```text
学习单元通过文字审校
  ↓
Worker 返回文字和真实剧照状态
  ↓
Worker 后台调用 Agnes
  ↓
技术校验
  ↓
写入 R2
  ↓
页面最多静默刷新一次
```

后台任务要求：

- 不阻塞每日知识响应。
- 以 `knowledgeUnitId + locale + imageStyleVersion` 幂等。
- `generating` 状态防止并发重复生图。
- 最多自动重试一次。
- 失败后标记 `unavailable`，不循环重试。
- 图片生成不占用文字 AI 配额，但使用独立限流和总开关。
- 用户离开页面后不继续刷新 UI。
- 用户正在答题时不插入图片或改变滚动位置。

### 9.5 图片技术校验

至少检查：

```text
MIME 类型
图片可解码
宽高合法
文件大小合法
不是空白图或错误 HTML
存储上传成功
资源地址可访问
```

每次模型、提示词或视觉风格变化后抽样 20 张，检查：

```text
概念相关性
是否出现真实演员脸
是否复刻具体电影场景
是否出现错误文字
是否造成科学误导
是否过度片透
是否符合视觉风格
```

严重误导、错误演员肖像、明显概念不匹配必须为 0 条；发现问题立即关闭该风格版本的后台生图。

## 10. Worker 与 Android 契约

### 10.1 locale

每日知识和答题请求增加可选：

```json
{
  "locale": "zh-CN"
}
```

允许：

```text
zh-CN
en-US
ja-JP
ko-KR
```

实际序列化时保留旧客户端默认行为，默认语言为 `zh-CN`。

### 10.2 缓存隔离

每日知识缓存键包含：

```text
daily + friendId + date + locale + watchedDigest
```

答题缓存键包含：

```text
quiz + sessionId + locale + watchedDigest + excludedQuizIds
```

旧缓存继续可读，语言切换不覆盖原语言历史。

### 10.3 专有名词

动态内容可以由 Worker 按 locale 生成，但影片名、人物、历史事件、机构和科学术语优先使用本地可靠数据。

不要让 AI 自由创造片名译名，也不要把 AI 翻译后的专有名词覆盖本地媒体数据。

## 11. Worker 服务端生图安全边界

Agnes 由 `auth-worker` 服务端调用，Android 不保存 Agnes 凭证、不直接调用生图 API。

服务端负责：

```text
提示词组装
内容边界
模型配置
并发和限流
图片技术校验
R2 持久化
图片状态
失败降级
```

建议抽象 Provider 适配层：

```text
ConceptIllustrationProvider
└── AgnesIllustrationProvider
```

配置使用 Worker Secret 或受控环境变量，不写入源码、Git、APK、BuildConfig、Pages 静态文件或日志。

第三方原始图片 URL 不作为长期资源直接暴露；生成成功后优先复制到 R2 或等价的受控持久化存储。

## 12. 学习历史与离线

本地保存最近：

```text
30 天或 50 条，以较小者为准
```

记录：

```text
知识单元 ID
展示日期
关联影视
主学科
核心概念
是否完成即时小题
答题结果
用户反馈
```

用户可以从每日知识页面进入“最近学过”，不新增底部导航栏。

已掌握内容降低再次推荐概率，但不删除。当天内容、历史内容和已缓存的图片均可离线阅读。

## 13. 无障碍与自适应

- 正文不使用固定高度。
- 标题允许自然换行，不截断关键结论。
- 系统字号放大时卡片自然撑开。
- 颜色不是区分事实、解读和错误的唯一方式，同时使用文字和图标。
- TalkBack 不逐字播报动态文本。
- 题目选项提供明确的选中、正确和错误语义。
- 开启减少动态效果后，正文和图片立即显示，取消淡入、缩放和位移动画。
- 图片提供描述性 `contentDescription`，但不得在描述中泄露隐藏片透内容。
- 小屏、横屏和大字号下，知识结论、影视标题和即时小题仍优先可见。

## 14. 状态与错误处理

### 14.1 加载

使用标题、影视标签、结论和解释骨架；不要只显示大面积旋转圈。

### 14.2 离线且有缓存

```text
当前为离线缓存
```

内容仍可阅读，已缓存的即时小题仍可作答。

### 14.3 离线且无缓存

```text
今天还没有准备好新的影视知识
连接网络后再试
```

### 14.4 AI 内容失败

内部失败原因只写日志，不向用户展示模型、审校器或 Provider 错误。按三级降级链选择：

```text
直接关联
  ↓
观影延伸
  ↓
审核种子知识
  ↓
上一条可读缓存
  ↓
明确空状态
```

### 14.5 图片失败

保留文字、真实剧照或学科图标；概念插图单独显示不可用，不阻断阅读和答题。

## 15. 测试与验收

### 15.1 Worker 测试

覆盖：

- locale 校验和缓存隔离。
- 学习单元字段完整性。
- 二阶段审校重写。
- 泛化内容拒绝。
- 事实、解读、延伸类型边界。
- 来源 URL 和来源依据。
- 物理、化学、医学等证据门槛。
- 片透等级。
- 即时小题与学习单元一致。
- 审校失败使用种子知识，不返回第一轮候选。
- 生图任务幂等、状态转换、失败重试和降级。
- R2 资源地址和图片技术校验。
- 旧缓存和旧字段兼容。

### 15.2 Android 测试

覆盖：

- 新旧每日知识 DTO 解码。
- 多语言请求和缓存键。
- 每日知识首屏信息层级。
- 展开概念解释。
- 即时小题答对、答错和解析。
- 真实剧照、海报、AI 概念插图和无图降级。
- 图片就绪后的单次静默刷新。
- 换题次数、当天稳定性和重复控制。
- 历史回看和离线状态。
- 大字号、TalkBack 语义和减少动态效果。
- 旧缓存显示不崩溃。

### 15.3 内容抽样验收

每次提示词、模型、学科规则、来源策略或图片风格变化后：

- 抽检 20 条每日知识。
- 检查核心事实错误为 0。
- 检查明显泛化为 0。
- 检查无法指出影视依据的内容最多 1 条。
- 检查片透等级错误为 0。
- 检查图片严重误导为 0。
- 总体合格率至少 90%。

Mock 测试只能证明结构和规则链路，不能代替真实 MiMo / Agnes 内容质量验收。

## 16. 实施顺序

### P0：内容契约与质量链

- 扩展共享学习单元和 locale 契约。
- 建立学科目录、关联等级和证据模式。
- 完成候选生成、二审、本地门槛和种子知识降级。
- 保留旧字段、旧缓存和旧答题协议。

### P1：每日知识与答题体验

- 改名为“今日影视知识”。
- 实现主知识卡、影视依据、概念展开和即时小题。
- 增加内容反馈、难度反馈和每日换题边界。
- 加入无障碍、减少动态效果和多语言 UI。

### P2：真实剧照与 AI 插图

- 使用媒体 ID 接入现有 TMDB / 豆瓣图片资源。
- 增加图片角色、来源和片透字段。
- Worker 服务端接入 Agnes。
- 后台预生成、R2 持久化、状态返回和单次静默刷新。
- 完成图片技术校验和抽样验收。

### P3：历史、离线和持续质量

- 最近 30 天或 50 条历史。
- 离线回看和图片缓存。
- 反馈驱动的候选选择。
- 建立版本化内容抽检记录。
- 通过真实调用验收多语言、科学学科和图片质量。

## 17. 完成定义

只有同时满足以下条件，才可称为本设计完成：

```text
每日知识不再以“冷门”作为硬目标
每条内容有明确概念和具体影视依据
事实、解读、延伸科普边界清楚
二审失败不返回第一轮候选
答题和每日知识共享学习单元
即时小题不额外消耗文字 AI 配额
真实剧照和 AI 插图角色分离
AI 插图由 Worker 生成并持久化
图片失败不影响正文和答题
locale 和缓存隔离正确
历史内容可离线回看
正文首屏可读、可访问、可放大
学科覆盖不硬凑，物理化学等有证据门槛
测试覆盖结构、规则、兼容、UI 状态和降级
真实模型内容通过抽样验收
```
