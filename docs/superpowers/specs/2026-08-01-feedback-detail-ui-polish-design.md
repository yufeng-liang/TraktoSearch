# 反馈详情页 UI 优化设计

> 日期：2026-08-01
> 状态：已获用户确认，待实现
> 范围：Android Compose 反馈详情页及其新建反馈导航流程

## 背景

当前反馈详情页存在两个明显问题：

1. “写新反馈”按钮被放在对话列表末尾，容易与当前反馈的回复动作混淆。
2. 底部回复栏使用底部对齐，截图、输入框、加图标和发送按钮在不同状态下无法保持垂直居中。

详情页还需要在保持现有消息定位、回复、截图预览和关闭状态行为的基础上，改善信息层级与视觉一致性。

## 目标

- 形成清晰的“标题栏、反馈内容、对话、回复栏”层级。
- 将新建反馈入口移至标题栏右侧，避免把独立反馈误认为当前对话的一部分。
- 让回复栏在无截图、有截图、上传中、发送失败和键盘弹出时保持稳定布局。
- 保留从消息页进入详情后的回复定位和高亮行为。
- 保留现有品牌化 Compose 视觉，不引入新的数据协议或网络接口。

## 非目标

- 不调整反馈 API、DTO、Repository 或 ViewModel 的数据协议。
- 不重做消息列表筛选、消息解析和已读逻辑。
- 不改变截图上传数量限制和全屏查看功能。

## 设计决策

| 决策项 | 方案 |
| --- | --- |
| 视觉方向 | 品牌化原生 Compose，沿用现有米色/棕色主题 |
| 页面结构 | 标题栏 + 可滚动详情/对话 + 固定底部回复栏 |
| 新建反馈入口 | 详情标题栏右侧 `+` 图标；反馈列表页保留顶部新建卡片 |
| 新建成功去向 | 返回反馈列表并刷新，不返回原反馈详情 |
| 原始截图 | 固定高度的纵向缩略图，使用 `ContentScale.Fit` 保留完整内容，点击后全屏查看 |
| 环境信息 | App 版本和设备紧凑展示；Trakt、豆瓣、联系方式仅在有值时显示；默认展开 |
| 对话样式 | 开发者左侧、用户右侧的聊天气泡，保留头像、角色名、时间和附件预览 |
| 已关闭反馈 | 隐藏回复栏，底部显示关闭状态；仍可从标题栏创建独立反馈 |
| 消息深链 | 继续通过 `replyId` 自动滚动到目标回复并短暂高亮 |

## 页面结构

### 标题栏

- 左侧为返回按钮。
- 中间显示反馈展示 ID，例如 `#BUG001`；加载或无展示 ID 时回退到反馈标题。
- 右侧为 `+` 图标按钮，使用本地化无障碍描述，点击进入新建反馈页。
- 不在对话内容末尾重复放置“写新反馈”文字按钮。

### 可滚动内容

内容使用 `LazyColumn`，从上到下依次为：

1. 原始反馈卡片。
2. 有回复时显示“对话”标题。
3. 按时间顺序显示左右聊天气泡。

原始反馈卡片包含类型、状态、正文、完整比例截图和紧凑环境信息。长正文仍允许自然换行，截图点击继续进入现有全屏查看器。

聊天气泡最大宽度约为可用宽度的 80%，开发者使用中性表面色，用户使用主题主色。头像、角色名和时间保持统一对齐，截图作为气泡内附件预览。

### 回复栏

非 CLOSED 状态下，回复栏固定在可滚动内容下方，并适配系统导航栏和输入法 inset。

- 已选择的截图单独显示在输入行上方。
- 输入行使用 `Alignment.CenterVertically`，依次放置加图标、可增长输入框和固定尺寸发送按钮。
- 输入框支持 1～4 行，按钮尺寸固定为 48dp，避免多行文本改变按钮位置。
- 上传中或发送中锁定输入控件，发送按钮显示进度。
- 失败信息显示在回复栏内，不清空草稿和已选截图。
- 回复成功后清空草稿和本地截图，并重新加载当前详情。

CLOSED 状态隐藏加图、输入和发送控件，显示居中的关闭提示。

## 导航与状态流

1. 从反馈列表或消息列表进入详情时，继续使用共享的 `FeedbackViewModel`。
2. 详情加载完成后继续标记当前反馈为已读。
3. 如果路由携带 `replyId`，详情数据加载完成后滚动到对应回复并执行现有短暂高亮；目标不存在时不阻塞页面。
4. 点击标题栏 `+` 进入新建反馈页。
5. 新反馈提交成功后返回反馈列表，并触发列表刷新，使新反馈可见。
6. 回复成功后留在当前详情页，刷新详情以显示新回复。

## 本地化与无障碍

- 所有新增用户可见文字同步 `values`、`values-zh`、`values-ja`、`values-ko`。
- App、设备、Trakt、豆瓣等标签不得在 Composable 中硬编码英文。
- 返回、创建反馈、添加截图、删除截图和发送按钮提供本地化 `contentDescription`。
- 图标按钮保持稳定尺寸，触摸目标不小于 48dp。
