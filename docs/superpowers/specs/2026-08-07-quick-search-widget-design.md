# QuickSearchWidget 启动组件优化设计

## 目标

将现有的纯 Glance 文字组件改造成符合 TrackToSearch 视觉风格的桌面启动组件。组件不承担搜索输入或网络数据展示，只负责可靠地把用户带到 App 的统一搜索页。

当前组件的点击行为是直接启动 `MainActivity`，尺寸声明约为 `3×2`，内容是居中的硬编码文本。统一搜索页实际由 `MainScreen` 的第 0 页承载，空搜索状态已经由现有 `SearchScreen` 提供。

## 产品契约

- 组件只有一个动作：点击整张组件，打开 App 的统一搜索页。
- 组件不提供输入框、键盘、搜索按钮、最近搜索词、推荐海报、网络状态或动态推荐内容。
- 点击后不自动弹出软键盘，保留搜索页现有的首屏布局和焦点行为。
- App 已在前台时，重复点击只切换到搜索页，不创建重复的页面入口。
- 缺少或无法识别启动意图时，App 保持原有默认启动行为。

## 启动与授权流程

Widget 使用显式的打开搜索意图启动 `MainActivity`。意图应使用内部常量标识，不依赖带空关键词的 `Routes.SEARCH` 路由，因为该路由面向已有搜索词的结果页面。

### 冷启动

1. `MainActivity` 读取打开搜索意图并保留请求状态。
2. 已授权、离线授权或访客模式完成启动初始化后，以 `MainScreen` 搜索页（第 0 页）作为初始页。
3. 未激活时沿用现有激活页流程，不绕过授权保护。
4. 激活成功或进入访客模式后，如果仍有待处理的 Widget 请求，则进入搜索页；没有 Widget 请求时保持现有默认页逻辑。

### 热启动

- `onNewIntent` 接收到打开搜索意图时，向当前导航状态发送幂等的打开搜索请求。
- 当前主页面消费请求并切换 Pager 到第 0 页。
- 请求消费后立即清除，避免旋转、重组或再次恢复时重复跳转。

## 视觉设计

采用 **Adaptive Ticket** 方向：以 App 的 Material 表面语言为基础，使用克制的票券式强调色，不绘制不可编辑的假输入框。

### `2×1` 紧凑布局

- 使用现有 App 启动图标作为品牌识别。
- 显示主文案「快速搜索」。
- 右侧显示箭头，提示整卡可以进入搜索页。
- 隐藏应用名和范围说明，优先保证四种语言下的可读性。

### `4×2` 完整布局

- 左侧为 App 启动图标。
- 显示应用名资源、主文案「快速搜索」和辅助文案「电影 · 剧集 · 资源」。
- 底部使用扁平的动作行「快速搜索」与箭头，不使用写着「打开搜索」的胶囊按钮，避免暗示存在独立的第二个点击目标。
- 所有内容保持在同一个可点击根容器内。

### 主题与颜色

- 明暗表面跟随系统桌面环境，分别提供高对比的浅色和深色颜色组合。
- 强调色读取 App 当前保存的 Monet 主题色，使组件与 App 当前主题保持一致。
- 读取主题失败或旧数据无法解析时，回退到 Vintage Ticket 棕色强调色。
- 不读取网络数据，不根据海报或搜索结果改变组件外观。
- 主题设置保存成功后，主动刷新所有 QuickSearchWidget 实例，使桌面组件立即同步颜色。

### 尺寸策略

- 只维护两个稳定设计断点：`2×1` 和 `4×2`。
- Widget provider 的最小尺寸调整为能承载 `2×1` 紧凑布局，完整目标尺寸对应 `4×2`。
- 中间或异常尺寸统一回退到紧凑布局，不让多语言文案在压缩过程中发生重叠、截断或布局跳变。
- Glance 内容根据实际可用尺寸选择布局，不依赖桌面厂商固定的单一网格换算。

## 组件实现边界

修改范围包括：

- `app/src/main/java/com/tracktosearch/widget/QuickSearchWidget.kt`
- `app/src/main/res/xml/quick_search_widget_info.xml`
- `app/src/main/java/com/tracktosearch/MainActivity.kt`
- `app/src/main/java/com/tracktosearch/ui/navigation/AppNavigation.kt`
- `app/src/main/java/com/tracktosearch/ui/screen/main/MainScreen.kt` 或等价的现有导航状态边界
- `app/src/main/java/com/tracktosearch/data/local/ThemeStorage.kt` 的只读主题数据接入边界（如现有 API 足够则不扩展其职责）
- `values/`、`values-zh/`、`values-ja/`、`values-ko/` 下的 Widget 文案

实现要求：

- 移除 Widget 中硬编码的应用名和提示文字，统一使用资源。
- 沿用现有 Glance、Material 颜色和本地主题存储，不引入新的网络层、图片下载器或持久化结构。
- 点击根容器使用单一启动动作；不增加多个点击区域。
- 主题刷新只触发 Widget 更新，不触发搜索或其他业务请求。
- Widget 无法读取主题时必须仍能正常渲染和启动 App。

## 本地化与无障碍

新增或调整以下语义，四种语言保持同步：

- 紧凑主文案：快速搜索
- 完整范围说明：电影 · 剧集 · 资源
- 整体无障碍描述：快速搜索，打开统一搜索页

英文、日文和韩文版本应采用自然短文案，不直接复用中文长度。应用名通过现有 `app_name` 资源读取，不在 Kotlin 或 Glance 内容中硬编码。

## 错误与回退

- 主题读取失败：使用固定 Vintage Ticket 颜色继续渲染。
- 尺寸无法匹配：使用 `2×1` 紧凑布局。
- 打开搜索意图缺失：保持 App 当前默认启动流程。
- Widget 在 App 进程未启动时：由系统启动 `MainActivity`，由 Activity 的启动初始化决定授权页或主页面，不在 Widget 侧复制授权逻辑。
- 重复收到相同打开搜索请求：只保留一次待处理状态，导航消费后清除。

## 验证方案

### 源码与测试

- 测试打开搜索意图的解析、冷启动待处理状态和热启动幂等消费。
- 测试授权完成或进入访客模式后，待处理请求最终进入搜索页。
- 测试无意图启动仍保持原有默认页行为。
- 测试主题读取失败和未知尺寸回退路径。
- 运行 Widget、导航和 Activity 相关针对性测试，并执行 `assembleDebug`。

### 模拟器验收

- 在浅色和深色系统环境分别放置 `2×1`、`4×2` 组件，检查表面、强调色、图标和文字层级。
- 验证桌面点击后的冷启动、热启动、已授权、离线授权、访客和未激活流程。
- 在 App 内切换 Monet 主题后确认桌面组件即时刷新颜色。
- 检查 UI 树和无障碍节点，确认整卡只有一个可访问的启动动作。
- 检查中文、英文、日文和韩文的长短文案不重叠、不截断、不改变组件尺寸。
- 记录安装结果、启动进程、UI 树、截图和 `logcat -b crash`；构建成功不单独视为功能和视觉验收通过。

## 非目标

- 不在 Glance 中实现可编辑搜索框或键盘输入。
- 不在桌面组件中执行搜索请求、网络刷新或推荐数据加载。
- 不展示用户最近搜索词、搜索历史、海报或账号信息。
- 不新增多入口快捷操作，例如电影搜索、剧集搜索和资源搜索分区点击。
- 不重构现有 `SearchScreen` 的搜索业务和视觉交互，只为 Widget 打通打开第 0 页的入口。
