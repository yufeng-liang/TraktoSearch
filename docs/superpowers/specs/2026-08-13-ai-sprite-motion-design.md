# 搜索页 AI 精灵角色动效设计

> 状态：待用户审阅
>
> 日期：2026-08-13
>
> 范围：Android Jetpack Compose 搜索页 AI 精灵主动触发、角色资产与可复用动效契约

详情页复用边界：本任务不修改 `DetailScreen.kt` 或详情页业务文件。公共契约固定在
`com.tracktosearch.ui.screen.ai`，详情页后续通过传入自身布局得到的 `Rect` 复用同一套角色资产、状态和渲染入口。

## 1. 目标

将搜索页的 AI 精灵主动触发从“浮出一个头像和功能面板”升级为有角色辨识度的短动作：角色从云朵、搜索框边缘或结果卡片旁出现，先观察用户，再做一个轻回应，最后自动收回。动效必须服务搜索流程，不遮挡输入、结果点击和滚动。

本次设计的第一验收标准不是“动画是否流畅”，而是“看到角色轮廓和动作时，是否能认出它是对应的 Chiikawa 角色”。角色外形、线条、脸部五官、腮红、耳朵/头部特征和动作性格优先于装饰效果。

## 2. 现状与问题

当前实现包含三类自动触发：`FIRST_ENTRY`、`SEARCH_COMPLETED` 和 `IDLE`。搜索页通过 `AiSpriteOverlay` 显示角色头像、文案和四个功能按钮；角色本体由 `AiCharacterGlyph` 使用一个 Canvas 绘制通用圆脸，仅按角色 ID 改变颜色和少量耳朵形状。

仓库已有天气与彩蛋 Lottie，可作为云朵环境层，但没有 AI 角色专属动画。工作区外的角色资产目录 `F:\website-trakt\assets\chiikawa` 已有可复用的角色参考素材，包括：

- `ai-chiikawa-peek.png`：吉伊从竖直边缘探头并抓住边缘，适合搜索框边缘露头。
- `chiikawa-spawn.png`：吉伊正面全身姿态，适合云朵后出现。
- `chiikawa-hi.png`：吉伊挥手/回应姿态，适合结果完成后的短回应。
- `ai-hachiware-peek-v3.png`：小八从边缘探头，带蓝色头部特征。
- `ai-usagi-peek-ground-v9.png`：乌萨奇从地面探出，带长耳朵和黄色体色。

这些素材是角色视觉基准，不代表可以直接把整张 PNG 当成动画。若整张图片只做平移、缩放或淡入，仍然属于贴图运动，不能作为最终方案。

## 3. 设计原则

### 3.1 角色资产先于动作

搜索页自动动效只允许使用具有专属形体资产的角色。角色必须至少具备以下可核对特征：

| 角色 | 必须保留的视觉特征 | 动作性格 |
| --- | --- | --- |
| 吉伊 | 白色圆润身体、圆耳、粗黑轮廓、大眼睛高光、粉色椭圆腮红与条纹、小嘴和短手短脚 | 胆小、谨慎、先观察再靠近；幅度小，回弹柔和 |
| 小八 | 白色脸部、蓝色头部/耳部区域、粗黑轮廓、大眼睛高光、粉色腮红 | 温柔、乐观；探头后轻轻点头或挥手 |
| 乌萨奇 | 黄色身体、长耳、粉色耳内区域、粉色腮红与黑色轮廓 | 反应快、节奏跳脱；短促弹出，耳朵和身体有更明显的回弹 |

飞鼠、狮萨、栗子馒头和獭师在没有同等质量的专属角色资产与动作参考前，不进入搜索页自动探头动画；现有精灵中心可以继续使用兼容的静态展示。不能用通用圆脸 Canvas 假装这些角色已完成。

### 3.2 统一动作语法

每个主动触发遵循同一条动作语法：

`预兆 -> 露出 -> 观察 -> 小回应 -> 收回`

动作只表达陪伴感，不表达搜索加载成功、结果数量或错误状态。真实业务状态仍由搜索结果、加载指示和文本承担。

### 3.3 轻量、可中断、可恢复

- 用户开始输入、搜索框获得焦点、清除搜索词、滚动结果、开始新加载或打开其他浮层时，当前角色立即进入 `INTERRUPTED` 并收回。
- 角色自动出现时不再自动展开四项 AI 功能按钮；点击角色或提示入口才打开现有精灵中心。
- 点击、长按云朵的既有彩蛋和精灵中心入口保留，自动角色动画不能改变短按/长按语义。
- 遵循系统减少动态效果设置；关闭动效时保留最终静态角色或语义入口，不依赖动画传达功能。
- 角色动画结束后停止无限循环。待机不使用持续抖动、持续眨眼或持续粒子。

## 4. 角色资产与分层方案

### 4.1 资产来源与使用边界

实现时优先将 `F:\website-trakt\assets\chiikawa` 中已经确认的角色素材复制为 App 本地资源，并保留其原始视觉比例、黑色轮廓粗细和透明边界。资源进入 App 前必须检查：

1. 是否为真正的透明背景，不能出现白底、黑底或抠图光晕。
2. 角色主体是否被裁掉耳朵、脚、手或抓边缘的爪子。
3. 在 72dp、96dp、128dp 三个显示尺寸下，眼睛高光、腮红条纹和轮廓仍可辨识。
4. 左右镜像后，耳朵、手和脸部特征是否仍然自然；不能简单镜像带有明显方向性道具的姿态。

素材属于项目现有的非官方角色风格资源，产品文案不得声称官方授权、合作或背书。自动动画使用的资源和官网现有角色资源应保持同一视觉来源，不混用通用几何头像。

### 4.2 分层要求

每个进入自动动画的角色至少拆为以下图层：

- `body`：身体与脚，负责整体重量、轻微压缩和上下移动。
- `head`：头部主体，负责观察方向与轻微转动。
- `ears`：左右耳朵独立，允许不同步抖动；乌萨奇需要独立长耳图层。
- `face`：眼睛、眼睛高光、眉/额头线、嘴和腮红；至少支持眨眼和视线方向变化。
- `arms`：手/爪，支持抓住边缘、挥手或短促回应。
- `effects`：可选的小火花、汗滴或心形，只用于回应瞬间，不能遮挡脸。

如果原始 PNG 不能直接无损拆层，应以该 PNG 为视觉参考重新制作分层资源，不能把整张图裁成几个矩形后硬拉造成接缝。分层图层需要共用同一基准画布和锚点，避免进入/退出时角色比例漂移。

### 4.3 角色专属动作参数

新增角色艺术配置，不把角色差异散落在 Composable 的 `if (character.id == ...)` 中。配置至少包括：

- 资源键与默认朝向。
- 头、耳、身体、手臂的锚点和安全变形范围。
- `PEEK` 的最大露出距离与停留时长。
- 观察方向顺序和眨眼间隔。
- 回应动作类型，如点头、挥手、耳朵弹动或短跳。
- 颜色和轮廓只作为资产检查辅助，不能替代角色图片。

## 5. 动画渲染技术方案

推荐使用 Compose 分层图层 + `Animatable`/弹簧动画 + 裁剪容器：

- 每个角色图层使用 `Image` 或本地矢量/位图绘制。
- 外层 `Box` 提供空间锚点和裁剪；角色本体不负责决定搜索框位置。
- `graphicsLayer` 只做小幅位移、旋转和缩放，变形范围由角色配置限制。
- `Animatable` 或 Compose spring 控制进入、观察、回应和收回；动画状态可被协程取消。
- 角色图层使用稳定资源引用，避免每帧重新创建 Painter、Path 或大对象。
- 云朵继续复用现有 `CloudEasterEgg` 的 Lottie；角色与云朵分层，云朵前景负责遮住角色下半身，形成真实“从云后出现”的关系。

不推荐直接把角色做成一段独立 Lottie：当前工程没有角色 Lottie，外部整段动画难以与搜索框坐标同步，也难以在输入/滚动时立即收回。只有在后续已有美术交付真正按角色分层的 Lottie 时，才允许把某一段动作替换为 Lottie，且必须保留同样的锚点、打断和减少动态效果接口。

## 6. 搜索页三类触发

### 6.1 首次进入：云朵探头

触发条件：当前账号已经激活角色，首次进入搜索页且本次页面会话尚未播放过首次动画。

时序：

1. 云朵沿用现有天气/节日 Lottie，先做一次轻微抖动或缩放预兆。
2. 角色从云朵下缘升起，先露耳朵和眼睛，再露出头部；身体保持在云朵前景之后。
3. 吉伊左右看一次并眨眼；小八轻点头；乌萨奇做一次短促弹动。
4. 角色停留约 500-700ms 后收回，云朵恢复原本循环。

整个动作建议控制在 2.2-2.8 秒，不显示大面积功能面板。点击角色/入口才打开精灵中心。

### 6.2 空闲触发：搜索框边缘露头

触发条件：搜索框未聚焦、查询为空、没有加载、用户保持空闲至少 8 秒，且冷却时间已过。首次进入或搜索完成动画刚结束时不立即叠加空闲动画。

实现要求：

- 使用搜索框实际 `LayoutCoordinates` 作为锚点，不使用状态栏高度和固定屏幕坐标推算。
- 角色位于搜索框 Surface 后方或边缘夹层，通过裁剪容器只露出耳朵、眼睛和部分脸/爪。
- 默认从搜索框较宽的一侧露头；窄屏或 RTL 布局需要选择不遮挡输入文本的一侧。
- 角色停留时只做一次小幅左右观察、一次眨眼或耳朵轻弹，不能持续抖动。
- 用户获得焦点、输入字符或点击搜索框时立即收回，搜索框宽度动画不被角色层改变。

建议总时长 1.5-2.0 秒，角色最大侵入搜索框内部不超过搜索框高度的 35%，不得覆盖搜索图标、输入文本和清除按钮。

### 6.3 搜索完成：首张结果卡片回应

触发条件：搜索由加载中转为完成、至少有一条结果、首张结果卡片已经完成布局，且当前没有焦点、滚动或其他浮层。

实现要求：

- 使用首张结果卡片的实际布局坐标作为锚点，不把角色固定在屏幕中央。
- 角色从卡片外侧短促弹出，先看向卡片，再做一次挥手/点头/耳朵弹动。
- 可出现最多两粒小火花或一个短气泡，但必须让卡片标题和点击区域保持完整可见。
- 动作结束后角色退回卡片边缘，不残留常驻装饰。

建议总时长 1.4-1.9 秒，短回应只播放一次。用户点击结果、开始滚动或下一次加载时立即取消。

## 7. 动画状态与触发优先级

建议新增独立的角色动效状态模型：

```text
HIDDEN -> PREPARE -> PEEK -> OBSERVE -> REACT -> RETREAT -> HIDDEN
                         \-> INTERRUPTED -> RETREAT -> HIDDEN
```

触发优先级固定为：

`FIRST_ENTRY > SEARCH_COMPLETED > IDLE`

同一时间只允许一个角色动画。新的高优先级触发取消低优先级动画；不会排队播放旧动画。

建议配额与冷却：

- 单次搜索页会话最多 3 次自动动画：首次进入 1 次、搜索完成 1 次、空闲露头 1 次。
- 每日最多 6 次，沿用现有 SharedPreferences 计数机制但按触发类型记录，避免首次进入和空闲触发互相耗尽。
- 空闲触发最短冷却 90 秒；搜索完成触发最短冷却 3 秒。
- 若角色艺术资产未就绪、精灵中心可见、云朵彩蛋可见、权限弹窗可见或用户正在交互，触发器返回空，不消耗配额。

现有 `AiSpriteOverlayPolicy` 的会话上限为 2，实施时需要改为按触发类型和冷却判断，不能继续用一个总计数让“首次 + 搜索完成”直接阻断主推荐的空闲露头。

## 8. 与现有组件的融合

### 8.1 `AiSpriteOverlay`

将其从“自动显示完整功能卡片”调整为“动效编排与点击入口”：

- 自动状态只渲染角色动作和必要的短提示。
- 角色点击打开 `AiSpriteCenter`；关闭和返回行为保持现有导航。
- 四项 AI 功能按钮继续放在精灵中心或用户主动打开的面板内。
- 云朵短按彩蛋和长按精灵中心入口不由角色 Overlay 接管。

### 8.2 `CloudEasterEgg`

云朵仍是环境层和既有彩蛋入口。首次进入动效只在其附近叠加角色层，不修改天气主题、Lottie 资源选择、短按彩蛋或长按行为。

### 8.3 搜索框与结果卡片

搜索框和首张结果卡片需要暴露可观测的布局锚点，角色层通过锚点定位。不能用一个全屏 `zIndex` 浮层覆盖所有内容，也不能让角色参与搜索框宽度和结果列表测量。

### 8.4 国际化和无障碍

任何新增可见提示都必须同步 `values/`、`values-zh/`、`values-ja/` 和 `values-ko/`。角色动画本身不依赖可见文字；语义树应提供稳定的“打开 AI 精灵中心”动作描述，并在减少动态效果时仍可操作。

帮助页应补充自动动效的行为说明：角色会在搜索页短暂探头，用户输入或滚动时会收回；云朵的短按/长按入口保持不变。

## 9. 公共复用契约

以下 API 属于跨页面公共入口，不能移动到 `SearchScreen` 包或在搜索页内私有化：

- `AiSpriteArt`：公共资产目录，提供 `AiSpriteArt.forCharacter(characterId)`、兼容函数 `automaticSpriteArt(characterId)` 和状态到资源的映射。角色配置不依赖页面。
- `AiSpriteMotionState`：稳定的公共状态枚举 `HIDDEN`、`PREPARE`、`PEEK`、`OBSERVE`、`REACT`、`RETREAT`。
- `AiSpriteAnchor`：稳定的公共锚点枚举 `Cloud`、`SearchBox`、`ResultCard`、`BottomPanel`、`DetailHeader`、`DetailPanel`、`RecommendationsTab`。
- `AiSpriteMotion(characterId, anchor, anchorBounds, visible, onClick, onFinished, modifier, interruptRequest)`：唯一的公共 Compose 渲染入口。`anchorBounds` 使用根坐标系 `Rect`，页面只负责采集坐标，不参与角色测量；`interruptRequest` 由宿主递增 `revision`，输入、焦点、滚动和页面切换都可中断。
- `AiSpriteMotionController`：可中断状态控制器，所有页面都通过 `interrupt(reason)` 进入 `RETREAT`，再由 `finishRetreat()` 回到 `HIDDEN`。

详情页适配时，底部面板入口使用 `BottomPanel`，详情头部使用 `DetailHeader`，详情内容面板使用 `DetailPanel`，相关推荐 Tab 或区域使用 `RecommendationsTab`。输入、滚动和页面切换都应调用同一个中断入口；这些适配不在本次搜索页实现中完成。

资源策略：app 运行时只引用 `R.drawable.ai_sprite_*` 的本地 drawable 资源键，不读取 `F:/website-trakt` 路径。当前 PNG 是从 website 资产目录导入后的 app 副本；保留原始 RGBA 透明边界，website 工程不作为运行时依赖，也不被本任务改写。

## 11. 测试与验收

### 10.1 单元测试

- 未激活角色、资产未就绪、弹窗/精灵中心可见时不触发且不消耗配额。
- 首次进入优先于搜索完成，搜索完成优先于空闲。
- 空闲必须满足空查询、未聚焦、未加载和空闲时长条件。
- 会话 3 次、每日 6 次、触发类型冷却和跨日恢复正确。
- 任一中断条件都进入收回状态，不留下“显示中”状态。

### 10.2 Compose/UI 测试

- 吉伊、小八、乌萨奇分别渲染对应资产，不再渲染通用圆脸占位图。
- 搜索框露头不会覆盖输入文本、搜索图标和清除按钮。
- 首张结果卡片回应不会阻断卡片点击；点击角色打开精灵中心。
- 输入、聚焦、滚动、加载时角色立即消失或收回。
- 减少动态效果设置下，角色保持可识别的静态状态和可访问入口。

### 10.3 设备视觉验收

设备验收至少记录设备分辨率、密度、API、安装结果和 `logcat -b crash`。分别截取：

1. 首次进入：云朵预兆、角色露出、动作停留、收回。
2. 空闲：搜索框边缘只有部分角色露出，文本和图标无遮挡。
3. 搜索完成：角色从首卡片旁弹出并退回，首卡片仍可点击。
4. 输入/滚动打断：角色在下一帧开始收回，无残影和布局跳动。

视觉检查必须对照 `ai-chiikawa-peek.png`、`chiikawa-spawn.png`、`chiikawa-hi.png` 等参考资产，核对轮廓、耳朵、眼睛高光、腮红条纹、颜色和比例。构建通过不能替代角色相似度验收。
