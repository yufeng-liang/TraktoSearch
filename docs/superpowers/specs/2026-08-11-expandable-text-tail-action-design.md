# 简介与评论尾部展开操作设计

日期: 2026-08-11
状态: 待评审

## 背景

详情页简介和评论正文共用 `ExpandableText`。当前组件把 `... 查看全部` 或 `... 收起` 作为普通文本拼接到正文末尾，操作文字不固定在尾行右侧，也没有截图中操作文字前的白化渐变。

## 目标

- 详情页简介和评论正文统一使用 `展开`/`收起` 操作。
- 正文折叠时最多显示 3 行，尾行最右侧显示主题色 `展开`。
- 展开时显示完整正文，尾行最右侧显示主题色 `收起`。
- 操作文字前的正文逐渐淡出到当前内容背景色，形成截图中的白化效果。
- 保持现有点击展开/收起、`rememberSaveable` 状态和长文本测量行为。
- 所有用户可见文案继续通过资源文件提供，英/中/日/韩四套资源同步更新。

## 非目标

- 不改变列表、推荐、季数等其他“查看全部”入口。
- 不改变简介或评论的最大折叠行数。
- 不改变评论翻译、剧透揭示和分页加载逻辑。
- 不新增网络请求、数据字段或 ViewModel 状态。

## 视觉与交互

### 折叠状态

正文超过 3 行时，显示经过尾部测量的正文前缀。前缀最后一段从正文颜色渐变到当前背景色，遮罩覆盖在操作文字左侧；右侧显示 `展开`，颜色为 `MaterialTheme.colorScheme.primary`。不再显示 `...`，由渐变承担截断提示。

### 展开状态

显示完整正文，操作文字改为 `收起`，仍放在最后一行最右侧并使用主题色。正文和操作文字之间保留足够的可读间距，不允许操作文字覆盖正文；当尾行空间不足时，测量逻辑应重新分配尾行内容，必要时让操作文字进入紧邻的尾行，不能遮挡正文。

### 点击与语义

沿用当前整段正文可点击的行为，点击后在展开和折叠状态之间切换。操作区域继续暴露操作文字，便于 Compose UI 测试和无障碍识别。

## 实现方案

继续保留 `ExpandableText` 作为简介和评论的共享入口，不复制两套 UI。

1. 使用现有 `TextMeasurer` 测量正文、操作文字、字体样式和可用宽度。
2. 折叠状态通过二分查找计算最长可见前缀，同时为尾部渐变和操作文字预留宽度，保证正文和 `展开` 位于同一尾行。
3. 尾行右侧使用独立的操作层定位，操作层的左侧使用从透明到 `MaterialTheme.colorScheme.background` 的水平渐变；浅色主题呈白化效果，深色主题不使用固定白色块破坏对比度。
4. 展开状态复用相同的尾行定位逻辑，使用完整正文和 `收起`，布局失败时优先保证正文完整可读，不允许操作文字覆盖正文。
5. 将资源键改为通用的 `detail_text_expand` 和 `detail_text_collapse`，因为同一组件同时服务简介和评论；四种语言分别使用对应的本地化动作短语。

## 测试

- 纯逻辑测试：短文本不产生操作；长文本产生 `展开`；展开后显示完整正文和 `收起`。
- Compose 测试：点击折叠文本后，`展开` 切换为 `收起`；短文本不显示操作文字。
- 资源检查：英/中/日/韩均存在通用展开与收起资源，且不再依赖旧的“查看全部”文案。
- 构建后使用 Android 模拟器或在线设备检查简介和评论两处的截图，确认操作文字在尾行右侧、渐变连续且没有遮挡正文；同时检查 `logcat -b crash`。

## 风险与回退

- 不同语言的操作文字宽度不同，必须使用实际资源文本测量，不能写死字符数或 dp 宽度。
- 详情页背景可能随海报主色变化，渐变终点使用主题背景色而不是固定白色，避免深色主题出现突兀白块。
- 如果设备上的 Compose 文本布局与 Robolectric 测量存在差异，以真实设备截图为视觉验收依据，并保留纯逻辑测试保护截断边界。
