# 资源高相关与详情/Watchlist UI 优化设计

- 日期：2026-08-12
- 状态：已完成头脑风暴与用户确认，待编写实现计划
- 范围：详情页资源高相关过滤、海报评分可读性、底部导航文字、Watchlist 分类 Tab 与想看/已看切换条

## 1. 背景与问题

详情页资源区域开启“仅显示高相关”后，截图中的 6 条资源全部被隐藏。前两条是明确的视频资源：

- `蜘蛛侠：崭新之日 最新`
- `蜘蛛侠：崭新之日（TC画质增强版）`

第 3～6 条包含完整片名，但同时包含 `FLAC`、`24bit`、`48khz` 和“中文推广曲”等音频信号。当前评分器将完整片名的定界命中计为约 40 分，再将内容标记扣分；前两条如果没有年份或已识别画质加分，也可能低于当前 45 分阈值。结果是影视视频被误杀，音频资源与视频资源没有被清晰区分。

详情页海报右上角的共享 `RatingBadge` 在白色或浅色海报上字号、图标和描边不足以保证可读性。详情头部右侧的多平台 `RatingsRow` 也需要适度放大平台图标、品牌字和分数，但不能改变评分值、来源槽位或固定高度布局。

Watchlist 目前有三类视觉需求：

1. 底部导航文字字号偏小。
2. 电影/电视剧/其他分类 Tab 的字号和垂直内边距偏大。
3. 标题栏“想看/已看”切换条当前使用等宽项；用户希望选中项按内容驱动占据超过一半宽度，字号放大，未选中项缩小，并在切换时平滑过渡。

## 2. 目标

- 保证完整影视标题命中的真实视频资源在高相关模式下可见。
- 保留对明确音频、电子书、专辑、原声带、剧集冲突和错年份资源的过滤能力，降低误放与误杀。
- 统一资源相关度排序与高相关过滤的判定依据，普通详情页和豆瓣失败项详情页行为一致。
- 提升海报右上角评分在浅色海报上的可读性，同时适度增强详情头部多平台评分区的层级。
- 放大底部导航文字但保留现有图标、等宽触控区和选中动画。
- 让 Watchlist 分类 Tab 更紧凑，让“想看/已看”切换明显表达当前模式；不改变 Watchlist 数据、网络和筛选逻辑。

## 3. 非目标与约束

- 不修改资源搜索 API、网盘源协议、`ResourceItem` 字段、缓存协议或请求策略。
- 不引入 Python/TypeScript 运行时或新的在线匹配服务。
- 不改动全局 `CapsuleTabSelector` 的其他页面行为；Watchlist 模式切换使用 Watchlist 专用实现。
- 不改变 IMDb、豆瓣、TMDB、RT 等评分数据和来源优先级。
- 不删除资源；高相关模式只改变当前展示列表，关闭后必须从 `allResources` 恢复完整有效结果。
- 用户可见文字继续使用现有 `stringResource` 体系；新增文案如有需要同步 `values/`、`values-zh/`、`values-ja/`、`values-ko/`。
- 代码注释使用中文；ViewModel 内部错误信息保持英文约定。

## 4. 资源高相关设计

### 4.1 现状根因

现有 `RuleBasedRelevanceScorer` 直接对完整资源名计算标题、年份、类型、地区、内容、画质和人物分数。完整片名定界命中通常为 `+40`；`FLAC`、`24bit`、`48khz` 等非影视内容标记会触发扣分。高相关过滤在详情页和豆瓣失败项页面均通过 `scoreMap[url] >= 45` 判断。

这个模型把两种不同问题混成一个分数：

- 资源是否明确指向目标影视；
- 资源内容是否是适合影视详情页展示的视频。

设计改为保留分数排序，但使用分层判定决定高相关资格。

### 4.2 发布名规范化与解析

在 `RuleBasedRelevanceScorer` 内增加纯 Kotlin 的规范化/解析逻辑，借鉴 GitHub 上 `parse-torrent-title`、`torrent-name-parser` 和 `rank-torrent-name` 的发布名拆分思路，但不引入外部运行时依赖。

规范化包括：

- 统一大小写；
- 统一全半角括号、常见标点和空白；
- 识别年份、分辨率、编码、容器、字幕、音频、发布组、版本和季集等技术元数据；
- 生成用于标题匹配的“标题候选片段”，避免把整条发布名当作影视标题参与余弦相似度计算。

解析结果至少区分：

- 标题匹配强度；
- 是否命中目标年份、是否存在明确冲突年份；
- 是否出现视频质量/容器/版本信号；
- 是否出现明确音频/书籍/专辑信号；
- 是否出现目标类型冲突（电影资源中的剧集/季集标记等）。

### 4.3 标题匹配分层

标题和原名分别参与匹配，取可信度最高者：

- **精确命中**：规范化后的资源标题与目标标题或原名一致，属于强匹配。
- **定界命中**：目标标题前后由标点、空格、数字、版本词或首尾包围，属于强匹配。中文标题中不能因为附加“最新”“TC画质增强版”等发布信息而降级。
- **部分相似**：仅有字符 bigram/相似度命中，属于弱匹配，只用于排序，不直接放行。

现有防误伤规则继续保留：`电子情书`、`给阿嬷的情书`、`夜港情书` 等不因包含短标题就获得强匹配。

### 4.4 高相关资格

高相关模式的放行规则：

1. 强标题匹配且没有明确冲突时放行。
2. 明确音频、电子书、专辑、原声带、配乐集等非影视类型时隐藏，即使完整片名命中。
3. 目标是电影而资源名出现 `第一季`、`第2季`、`Season 1`、`S01`、电视剧等剧集冲突时隐藏；目标是剧集时不因正常季集标记误杀。
4. 资源名存在明确影片年份且与目标年份冲突时隐藏。
5. 只有弱标题匹配时继续使用高相关阈值过滤。
6. 缺少影视上下文时不启用高相关过滤。
7. 如果结果中存在强标题匹配但没有明确冲突，强匹配不得因为缺少 `1080p/MKV` 等技术字段而被阈值误杀。

截图样本的预期结果：

| 资源名特征 | 高相关模式 | 原因 |
|---|---|---|
| 完整片名 + `最新` | 保留 | 强标题匹配，无明确冲突 |
| 完整片名 + `TC画质增强版` | 保留 | 强标题匹配，版本/视频信号 |
| 完整片名 + `FLAC/24bit/48khz` | 隐藏 | 明确音频资源 |
| 完整片名 + `原声带/专辑` | 隐藏 | 明确非影视内容 |
| 部分相似但非完整片名 | 按阈值过滤 | 弱匹配不能直接放行 |
| 完整片名 + 错年份 | 隐藏 | 明确身份冲突 |

### 4.5 排序与缓存

- `ResourceRepository.rank()` 继续返回按相关度排序的资源和 `scoreMap`。
- 分数仍用于排序：年份命中、画质、导演/演员命中为正信号；版本词可以作为弱正信号。
- 非影视标记不再通过简单扣分把影视身份分数压到阈值以下，而是写入独立的内容资格判断。
- 缓存仍只保存原始资源；分数和高相关判定是每个 `ResourceQuery` 的运行时结果，不能跨影视条目复用。
- 详情页 `DetailViewModel` 与豆瓣失败项 `DoubanItemDetailScreen` 均从全量 `allResources` 重新应用源、网盘类型和高相关过滤，确保开关来回切换不丢低相关项。

## 5. 详情页评分视觉设计

### 5.1 海报右上角共享评分徽章

修改共享 `app/src/main/java/com/tracktosearch/ui/component/RatingBadge.kt`：

- 星标由约 `11dp` 增至约 `14dp`。
- 数字由约 `10sp` 增至约 `13sp`。
- 横向间距和徽章内边距小幅增加，避免放大后挤压。
- 星标和数字使用更明显的四向深色硬描边，并保留轻微阴影。
- 保留无实色黑色 chip 的设计，避免遮挡海报主体。

该组件被 PosterCard、Discover、Watchlist、Person 等海报卡共享，因此修改会同步提升所有海报评分可读性。

### 5.2 详情头部多平台评分区

修改 `RatingsRow` 及其内部单项布局，保持当前两行四槽和 `64dp` 固定卡片高度：

- IMDb、豆瓣、RT、MTC 等平台图标适度放大；
- 平台名称字号提高一级；
- 评分数字字号提高一级；
- 评分数字增加更明确的对比阴影/描边，但保留当前评分分档颜色；
- 保留固定槽位、缺失值显示和豆瓣条目不回退到 MTC 的既有逻辑。

## 6. 底部导航视觉设计

修改 `MainScreen.kt` 中的 `NavTabItem`：

- 文字从 `10sp` 增至约 `12sp`；
- 图标尺寸、四等分触控区和底部导航高度保持不变；
- 文字与图标继续共享现有选中缩放动画，选中态、悬停态和焦点态逻辑不变；
- 确保中文、英文、日文、韩文标签在固定槽位内单行显示且不互相遮挡。

## 7. Watchlist Tab 视觉与交互设计

### 7.1 分类 Tab

修改 Watchlist 专用 `WatchlistCategoryTabs`，不影响其他页面：

- 分类名称由 `16sp` 调整为约 `14sp`；
- 单项高度由约 `52dp` 调整为约 `44dp`，缩小垂直留白；
- 保留三项等宽触控区、独立数量徽标、选中语义和 `1.05x` 绘制缩放动画；
- 选中项继续使用轻玻璃表面和主题色，数量徽标随选中态变化；
- 缩放只作用于绘制层，不改变布局测量与相邻项位置。

### 7.2 想看/已看切换条

在 Watchlist 页面引入专用切换条，不修改全局 `CapsuleTabSelector`：

- 切换条仍为胶囊形容器，点击区域覆盖每个完整选项；
- 选中项使用约 `1.4–1.5` 的 flex 权重，未选中项使用约 `0.8` 的 flex 权重，使选中项超过总宽度的一半；
- 选中项字号约 `18sp`，未选中项约 `14sp`；
- 选中项使用现有主题 primary/玻璃视觉，未选中项使用弱化前景色；
- 选中项宽度、位置、字号和绘制缩放使用约 `220–240ms` 的平滑 tween 过渡；
- 切换后旧项同步缩小、新项同步放大，不使用回弹；
- 保留 `selectedMode`、搜索收起、列表切换和现有 ViewModel 逻辑；
- 窄屏下优先保证两项可点击和文字不溢出，必要时使用最小宽度约束，而不是压缩到不可读。

## 9. 风险与回退

- 共享评分徽章放大后可能与海报左上角状态标签或底部年份标签产生视觉竞争；通过稳定内边距、固定尺寸和设备截图调整，不改变数据布局。
- 多平台评分区字号增大后可能在窄屏上出现溢出；保留固定槽位并优先使用紧凑间距、单行省略。
- 非等宽切换条的选中项放大可能接近相邻内容；通过固定触控区、绘制层缩放上限和最小宽度约束控制。
- 资源名规则对未知语言/新格式不应硬判为冲突；未知信号只影响排序，不直接隐藏。
- 如新规则仍出现全隐藏，保留强标题匹配的候选并在测试中记录具体资源名，避免再用全局降低阈值解决。

## 10. 完成标准

- 截图中的前两条视频资源在开启高相关后可见，音频资源按预期隐藏。
- 同名误召回、剧集/年份冲突和非影视资源仍能被过滤。
- 海报评分在浅色背景上清晰可读；详情多平台评分区更醒目但不溢出。
- 底部导航文字放大；Watchlist 分类 Tab 更紧凑；想看/已看切换条使用内容驱动宽度和过渡动画。
- 相关测试、Debug 构建和设备验收均有明确结果记录，未以单一层级证据代替其他层级验证。
