# 项目持久记忆

## 项目核心指令（来源：CLAUDE.md）

### 语言与风格
- 所有输出、注释、文档均使用中文
- 遵循项目已有约定和模式，修改前先了解架构

### 工作原则
1. **想清楚再写** — 不瞎猜，明确假设，不确定就问
2. **简单优先** — 不做多余的事，砍到刚好够用
3. **外科手术式改动** — 只动必须动的，不翻新没坏的东西
4. **目标驱动执行** — 先定成功标准，再对着标准做

### 工作方式
- 使用 Context7 查询最新的库/框架文档
- 有不清楚的地方用 brainstorming 随时询问用户
- 涉及 UI 设计时，启动可视化伴侣展现设计效果
- 重要修改前先说明计划，获得确认后再执行
- 完成任务后简要总结改动内容

### Git 规范
- 不主动 commit/push，除非用户明确要求
- commit 格式：`<type>: <描述>`（feat/fix/refactor/docs/style/test/chore）

### 安全审计
- 提到"审计""安全审计""漏洞扫描"等关键词时，自动激活 Java 审计 skills

### 工作流集成
- 典型开发流程：需求 → 规划 → 实现 → 审查 → 交接
- Bug 修复流程：诊断 → 修复 → 验证

### 配置同步
- 用户提到"同步配置""备份配置"等时，使用 cc-config-sync 处理
- settings.json 中的敏感信息提交前需脱敏
